# 공개 Q&A 게시판에서 모은 실제 질문

출처는 LS ELECTRIC Solution Square의 Q&A 게시판이다. 2026-09-22에 16건을 모았다.

**여기에는 글 번호와 주소, 그리고 질문을 우리 말로 다시 쓴 것만 적는다.** 질문
본문과 답변 본문은 저작권이 각 작성자와 LS ELECTRIC에 있으므로 저장하지 않는다.
작성자 이름, 이메일, 소속, 현장 위치 같은 개인정보도 옮기지 않는다.

## 어떻게 가져왔나

게시판은 자바스크립트로 본문을 그리는 구조라 단순 HTTP 가져오기로는 아무것도
오지 않는다. 화면을 그리는 자바스크립트 묶음 파일을 내려받아 안에서 호출 경로를
찾았다.

목록 조회(`/api/guest/ssqData/document/community/filter`)는 네 번 시도했으나 계속
500이 났다. `period`가 정수여야 하고, 그걸 맞추면 다른 칸에서 `eq(null)`이 난다.
로그인 세션이 필요한 것으로 보인다.

**단건 조회(`/api/guest/ssqData/document/{id}`)는 로그인 없이 된다.** 글 번호는
검색엔진 색인에서 제목과 함께 얻었다. 남의 서버이므로 호출 사이에 0.7초를 두고
16건만 받았다.

## 처음에 잘못 센 것

**제목만 보고 "16건 중 제품명이 3건"이라고 적었다가 고쳤다.** 본문까지 읽으니
제품명이 나오는 것이 **16건 중 11건**이다. 제목은 짧아서 제품명을 빼고 쓰는
경우가 많았다.

숫자가 세 배 넘게 틀렸고 결론도 반대로 갔다. 제목만으로 센 것을 본문을 본 것처럼
쓴 것이 잘못이다.

## 그래서 알게 된 것

### 1. 제품명이 낱말이 아니라 모델 코드 안에 들어 있다

제품명이 나오는 11건 중 **3건은 모델 코드 안에만** 있다.

```
LSLV3150H100-4COFD      H100 앞에 숫자 0
LSLV00055G100-4EONN     G100 앞에 숫자 5
lslv0055g1004eonn       g100 앞에 숫자 5, 뒤에도 숫자
```

지금 `document_scope.py`는 이름 앞뒤에 ASCII 영숫자가 없을 때만 인정한다. 위 셋은
**전부 안 걸린다.** 평가셋에는 `LSLV0075M100` 한 건뿐이었고 그마저 답변 불가
문항이라 "데이터로 가를 수 없다"고 적고 보수적인 쪽을 골랐는데, 그때 적어 둔
재검토 조건이 **모델 코드로 묻는 실제 질문이 모이면 다시 본다**였다. 모였다.

`lslv0055g1004eonn`은 뒤에도 숫자가 붙어서 오른쪽 경계까지 풀어야 걸린다. 그러면
잘못 걸릴 위험이 커진다. 값을 어떻게 잡을지 따로 봐야 한다.

### 2. 질문 하나에 물음이 여럿이다

25405는 물음이 일곱 개, 23814는 두 개, 25065는 세 개다. 평가셋의 문항은 전부
물음 하나짜리다. 실제 질문을 그대로 넣으면 "정답 근거"를 하나로 정할 수 없다.

넣을 때 물음 단위로 쪼개야 하고, 쪼갠 것을 원래 글 하나에서 나온 것으로 묶어
두어야 한다. 평가셋 형식을 바꿔야 한다.

### 3. 맥락이 길고 이미 해본 조치가 적혀 있다

23814는 "dr14, dr15, bA11, bA13, bA15에 모터 정보를 넣고 bA20 오토튜닝 2를
해봤다"까지 적혀 있다. 검색어로 쓰면 파라미터 코드가 잔뜩 들어간 긴 문장이 된다.
만들어 쓴 질문("S100 팬 수명 진단은 몇 시간을 기준으로 하나요?")과 길이도 성격도
다르다.

### 4. 색인 안 된 제품을 묻는 질문이 실제 거절 대상의 큰 몫이다

16건 중 4건이 iV5, iG5A처럼 우리가 색인하지 않은 제품이거나 카탈로그, PLC 영역이다.
지금 평가셋의 답변 불가 6문항은 가격, 납기, 타사 비교, 업체 소개, 자격증인데
성격이 다르다. **인접 제품군 질문을 어떻게 거절하는지**가 실제로 더 자주 걸린다.
